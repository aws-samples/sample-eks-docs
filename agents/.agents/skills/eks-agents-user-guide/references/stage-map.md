# Stage map: the guide's pages in the order to run them

Run the base first, then one stage at a time. Each stage is one page of the agents section of the Amazon EKS User Guide. "The loop" is the seven steps in `SKILL.md`: set the variable, apply, sync, roll, verify, compare. The order below satisfies every page's prerequisites. Where it differs from the guide's table of contents, the note says why.

## About the times

Times are approximate, per stage, and vary with the Region and the network. On the open source path every stage together takes about two and a half hours, in bastion mode or workstation mode. In workstation mode the probe pod that reaches an internal load balancer adds a little to the ingress, `signin`, `people` and `delegation` checks.

**AWS services path.** In the open source table, a stage notes "AWS services" where that path's variables or checks differ. The second table below lists that path's stages in their own order.

The confirming lines are the lines each stage prints. Values specific to an account are shown as placeholders.

## Why this order

- **The gateway (3) comes before MCP (7), on-behalf-of (8), tasks (15) and evaluations (14),** which each need it.
- **Ingress (5) comes before on-behalf-of (8).** The person's tokens come from the ingress user pool.
- **MCP (7) comes before on-behalf-of (8).** The `delegation` phase calls the person's tools on the MCP server.
- **Memory (13) comes before the `people` check,** which needs `enable_consolidation`.
- **Tasks (15) runs late,** because its agent uses the gateway image and is easier to confirm on a quiet cluster.

## AWS services path

Times are approximate, per stage, in workstation mode with no VPC endpoints and a self-signed internal load balancer. The pages' commands run in the order below, which differs from the open source table because each page's prerequisites on this path point elsewhere. Gateway and tasks agents each need an entry in `gateway_permitted_agents`. A roll that recreates nothing takes under a minute.

In bastion mode (private-only endpoint, the bastion, VPC endpoints at the end, no ingress, chat UI or on-behalf-of stages), the times are similar, plus the cost of Session Manager: each `run-stack.sh` call through the bastion takes 20-40 s, so a page with five wrapped commands spends a few minutes in Session Manager alone. The final `exercise.sh` then skips the ingress, chat, signin, people and delegation phases.
